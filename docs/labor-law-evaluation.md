# 公开法规语料评测：12 部劳动法规 + 50 道测试题

在真实公开文档上检验检索效果，并对比切块方式与 Top-k。全部离线运行，不调用语言模型。

## 复现

```bash
python scripts/sweep_labor_law.py
```

单独跑某个配置：

```bash
python -m knowledge_lens --db labor.sqlite3 ingest examples/labor-law --strategy article --chunk-size 800
python -m knowledge_lens --db labor.sqlite3 evaluate --cases examples/labor-law-eval.jsonl --k 5
```

## 语料

[`examples/labor-law`](../examples/labor-law) 收录 12 部现行劳动相关法律法规，共约 6.9 万字：劳动法、劳动合同法、劳动合同法实施条例、社会保险法、工伤保险条例、劳动争议调解仲裁法、就业促进法、劳动保障监察条例、职工带薪年休假条例、企业职工带薪年休假实施办法、女职工劳动保护特别规定、国务院关于职工工作时间的规定。

文本取自 [LawRefBook/Laws](https://github.com/LawRefBook/Laws)（整理自国家法律法规数据库）。依据《著作权法》第五条，法律、行政法规及其官方文件不适用著作权保护。本语料仅用于检索评测演示，不构成法律意见，以官方发布文本为准。

## 测试集

[`examples/labor-law-eval.jsonl`](../examples/labor-law-eval.jsonl) 共 50 题：

- **45 道可回答题**，覆盖全部 12 部法规。问题用日常口语提问（如“公司拖欠工资，员工能不能马上解除合同？”），不照抄条文。每题标注来源文件和一句**原文证据**，证据由脚本逐条核对确实存在于语料中。
- **5 道无关题**（如“Python 怎么给列表排序？”），语料里没有答案，理想结果是检索为空。

## 指标

- **条文命中率@k**：前 k 个检索片段里，有片段来自正确文件且完整包含原文证据。比“找对文件”更严格：切块把条文从中间切断也算没命中。
- **条文 MRR**：第一个命中片段排名的倒数取平均，越靠前越高。
- **文档召回率@k**：前 k 个结果里出现正确文件的比例。

## 结论

1. **按条文切块明显好于固定长度**。同样 500 字，Top-3 命中率从 69% 提到 78%：固定窗口会把一条法条切成两半，证据句落在两个片段里都不完整。
2. **块越大命中率越高，但代价是成本**。800 字块命中率最高，但接入大模型后每次要多送约 60% 的文字。实际项目要在命中率和 token 成本之间取舍，300 字按条文切块 Top-5（84%）是更省的折中。
3. **剩下的错误主要是“用词对不上”**。如问“购物卡代替工资”，原文是“以货币形式按月支付”；问“交费”，原文是“不收费”；问“怀孕的员工”，原文是“孕期”。BM25 只认字面重合，这类问题要靠向量检索或改写查询解决。
4. **BM25 不会拒答**。无关问题只要有一两个字重合就会返回片段。上线前需要加绝对分数阈值，或让大模型在证据不足时拒答（在线模式已做引用校验）。

## 局限

测试题由项目作者编写，与语料同时构建，没有独立留出集；结果说明这套检索在这类问题上的表现，不代表真实业务准确率。指标只衡量检索，不衡量大模型生成答案的质量。
