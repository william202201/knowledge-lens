# 项目讲解与设计取舍

## 三分钟演示

1. 执行 README 的两条启动命令，在页面询问“API 超过速率限制后应该怎么重试？”。
2. 指出离线模式是摘录，展示来源、片段 ID、字符位置和分数。
3. 询问“quantum penguin teleportation”，展示没有证据时拒答。
4. 运行 evaluate，解释检索指标与生成质量不是同一件事。
5. 打开 service.py，说明严格结构输出与引用校验的能力边界。

## 设计取舍

- 为什么先做 BM25：可解释、易复现、不依赖 embedding 服务，作为语义检索的对照基线。
- 为什么保留字符位置：不仅展示文件名，还能定位检索片段与检查引用。
- 如何保证更新不遗留旧知识：读完资料后事务重建，失败保持旧索引。
- 15% 分数阈值的局限：能过滤部分低分干扰，但不能当成置信度；应在独立语料校准。
- 如何扩大：倒排索引、语义检索、重排、缓存、文档版本、独立留出集、逐句支持评测。
